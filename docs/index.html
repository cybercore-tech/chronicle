01 / BUILT WITH INTENT

A place for every
meaningful change.

Tools earn their place by making the next step easier. Chronicle keeps a narrow focus: what changed in Git since your last look.

01 /

One tree. All the activity.

Discover repositories beneath configured roots, with a depth limit you control. Discovery stops at each repository boundary.

02 /

Only the new chapter.

Remember the last-seen commit for each repository and report commits since that checkpoint.

03 /

Uncommitted counts, too.

See modified, staged, and untracked counts alongside committed work. Loose ends stay visible.

04 /

Rewrites are a signal.

Report history changes that cannot be represented as a linear list of new commits.

05 /

A journal that accumulates.

Append timestamped Markdown digests to a daily file. GitHub origins produce clickable commit links.

06 /

Quiet when nothing moved.

Unchanged, clean repositories stay out of the digest unless you request them with --show-unchanged.

03 / MAKE IT YOURS

Your next session
starts here.

Bring Rust and Git. These Linux commands use sibling checkouts and adjust the published manifest’s machine-specific Cybercore path. Then add a configuration file for your repository roots.

TERMINAL / INSTALL 
# Run from a new workspace directory
git clone https://github.com/cybercore-tech/cybercore.git
git clone https://github.com/cybercore-tech/chronicle.git
cd chronicle
# Make the published manifest's local dependency portable (Linux):
sed -i 's|/home/raven/.sysops/cybercore|../cybercore|' Cargo.toml
cargo install --path . --locked
mkdir -p "$HOME/.config/chronicle"
# Save the configuration below as ~/.config/chronicle/config.toml
chronicle

CONFIG.TOML / THE ESSENTIALS

CONFIGURATION 
state_path = "~/.local/state/chronicle/state.json"
max_depth = 3
markdown_out_dir = "~/Notes/Chronicle"

[[root]]
path = "~/Devspace"

Set root paths to your own repository directories. --config selects another configuration file; --no-color disables terminal colors.

Does it scan inside each repository?

Discovery stops when it finds a .git directory or file. Chronicle reads Git state rather than monitoring every filesystem write.

Does it run in the background?

Each invocation scans, reports, and updates its checkpoint. Schedule the command yourself for periodic digests.

What should I know about roots and history?

Overlapping roots are not deduplicated. A rewritten history is flagged, but Chronicle does not reconstruct the rewrite. GitHub commit links require a GitHub origin.
